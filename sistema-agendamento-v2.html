Índice do Agendamento v2

    Design e UX do Agendamento v2.0

    Evoluindo a experiência do usuário para um fluxo guiado e intuitivo.

    1. O Conceito: "Agendamento Conversacional"

    A versão 2.0 abandona a abordagem de "formulário único" em favor de um **fluxo guiado em etapas (wizard)**. Em vez de sobrecarregar o usuário com todas as opções de uma vez, a interface faz uma pergunta de cada vez, adaptando-se às respostas para apresentar apenas as informações relevantes para o próximo passo.

    Principal Mudança de Paradigma:

    O fluxo agora começa com **"O quê?"** (Seleção do Serviço) em vez de **"Quando?"** (Seleção da Data). Isso resolve a lógica fundamental, pois a duração do serviço define a disponibilidade de horários.

    2. Etapa 1: "O que você precisa?"

    O que o usuário vê:

    A primeira tela apresenta **cards visuais e interativos** para cada serviço disponível. Cada card contém:

    • Nome do Serviço (ex: "Consulta Inicial")
    • Duração (ex: "60 min")
    • Preço (ex: "R$ 250,00")

    Por que é melhor?

    • Início Lógico: O serviço determina a duração, que é a base para calcular os horários livres.
    • Foco no Valor: A experiência começa apresentando o valor (os serviços), não um calendário genérico.
    • Visualmente Atrativo: Cards com ícones ou imagens são mais convidativos do que um formulário.

    3. Etapa 2: "Quando fica bom para você?"

    Após o usuário clicar em um serviço, a tela faz uma transição animada para a seleção de data e horário.

    O que o usuário vê:

    • Mobile: Um **seletor de datas horizontal e deslizável** com os próximos 7-10 dias.
    • Desktop: Um calendário tradicional.
    • Ao selecionar um dia, a área de horários abaixo é preenchida **dinamicamente** com botões contendo apenas os horários disponíveis, já filtrados pela duração do serviço escolhido.

    Por que é melhor?

    • Inteligente e Relevante: O sistema só mostra horários que realmente comportam o serviço selecionado.
    • Experiência Mobile Superior: O seletor horizontal é muito mais amigável ao toque.
    • Feedback Imediato: O usuário vê a disponibilidade real instantaneamente.

    4. Etapa 3: "Confirme seus dados"

    Com o usuário já logado, esta etapa é simplificada ao máximo para reduzir o atrito.

    O que o usuário vê:

    Uma tela de confirmação simples com os dados do usuário pré-preenchidos.

    • Nome: `[Nome do Usuário]` (pré-preenchido, não editável)
    • Email: `[Email do Usuário]` (pré-preenchido, não editável)
    • Telefone (WhatsApp):** `[Telefone do Usuário]` (editável, com uma nota: "Usaremos este número para enviar a confirmação.")

    Por que é melhor?

    • Esforço Mínimo: O usuário não precisa digitar informações que a aplicação já possui.
    • Foco na Ação: A única tarefa é verificar o número de telefone e prosseguir.

    5. Etapa 4: "Revise e Confirme"

    A etapa final dá ao usuário uma visão completa do seu agendamento antes de confirmar, garantindo segurança e transparência.

    Resumo do Agendamento:

    Serviço: Consulta Inicial (60 min)

    Data: Sexta-feira, 25 de Julho de 2025

    Horário: 14:00

    *Uma notificação de confirmação será enviada para o WhatsApp informado.

    Por que é melhor?

    • Previne Erros: Permite que o usuário revise tudo antes da confirmação final.
    • Aumenta a Confiança: O processo transparente deixa o usuário seguro sobre a ação que está prestes a tomar.

    6. Impacto Técnico da Versão 2.0

    A implementação deste novo fluxo exigirá algumas mudanças na estrutura do código:

    • Gerenciamento de Estado Local: A página `/agendar` precisará de um estado para controlar a etapa atual do wizard (ex: `const [step, setStep] = useState('service')`).
    • Animações de Transição: A biblioteca `Framer Motion` será usada para animar a transição entre as etapas, criando uma experiência fluida.
    • API de Disponibilidade Aprimorada: A API ou Server Action que busca horários livres precisará receber o `serviceId` como parâmetro para filtrar os horários com base na duração do serviço.
    • Novos Componentes: Será necessário criar novos componentes de UI, como o `ServiceCard` e o `HorizontalDatePicker`.

    Conclusão:

    A Versão 2.0 transforma o agendamento de uma tarefa funcional em uma **experiência agradável, guiada e à prova de erros**, que encanta o usuário e aumenta significativamente a percepção de qualidade do seu serviço.
